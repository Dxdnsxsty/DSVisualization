# 数据结构可视化

面向《数据结构》课程学习者的**开源、纯静态**算法可视化网站。分步播放算法执行过程，代码行、数据状态、变量与文字讲解由同一个步骤对象同步驱动。

算法与章节按《数据结构教程》（李春葆等，第 5 版）编排，共 **53 个演示、覆盖 9 个可视化章节**。

无登录、无后端、无数据库、无外部 API，可直接用 GitHub Pages 托管。

## 本地运行

需要 Node.js 20+，已在 Node.js 24.21.0 / npm 11.19.0 下通过校验与构建。使用 nvm 时，先启用已安装的 Node 版本，并确认 `node --version` 和 `npm --version` 可用。

```bash
npm install
npm run dev        # 打开 http://127.0.0.1:8888
```

其他命令：

```bash
npm run validate     # Trace 格式、算法结果与排序操作统计校验
npm run build        # 类型检查 + 构建到 dist/
npm run preview      # 本地预览构建产物
npm run standalone   # 构建并生成 dist/standalone.html 单文件版
```

打开后默认进入「算法地图」，选定算法即可进入工作台。桌面左侧固定为课程目录，中间从上到下是自定义输入、动画和播放控制，右侧是代码与变量。点「播放」或「下一步」即可看到动画、代码高亮、变量面板同步变化。

**发给同学最省事的方式**：执行 `npm run standalone`，把生成的 `dist/standalone.html` 直接发出去。它把 JS/CSS 全部内联，双击即可打开，不需要 Node、不需要服务器、不需要联网，课程群里传一个文件就能打开全部演示。

## 端口说明（Windows 报 EACCES 时看这里）

开发服务器默认监听 `127.0.0.1:8888`。如果出现 `listen EACCES`，表示系统拒绝监听该端口。可以检查 Windows 的 TCP 保留范围和本机监听情况：

```powershell
netsh interface ipv4 show excludedportrange protocol=tcp
netstat -ano | findstr ":8888"
```

如果终端提示 `Port 8888 is already in use`，可以检查是否已启动本项目。需要临时换端口时，运行 `npm run dev -- --port 8890`，并打开终端显示的地址。长期使用其他端口可以修改 `vite.config.ts` 中的 `server.port`。

## 部署到 GitHub Pages

1. 把仓库推到 GitHub，分支名为 `main`。
2. 在仓库 Settings → Pages → Build and deployment 中选择 **GitHub Actions**。
3. `.github/workflows/deploy.yml` 会在提交到 `main` 及向 `main` 提 PR 时执行算法校验、可运行示例、构建、单文件导出与浏览器回归；PR 只做校验，`main` 校验通过后才部署。检查失败会保留报告，无需任何密钥。
4. 若仓库名不是根域名，也不用改配置：`vite.config.ts` 使用相对 `base`，路由是 hash 形式，项目页路径可直接工作。

本地验证静态托管效果：`npm run build` 后用任意静态服务器打开 `dist/index.html` 即可。

## 功能范围

**已实现**

- **Trace 引擎**：`TraceStep[]` 状态序列 + 唯一 `currentStep`，倒放 / 拖拽进度天然一致
- **四类可视化场景**：数组、链表、树、图；另支持二维网格（矩阵 / 哈希表折行）与辅助结构条（归并目标数组等）
- **53 个演示**，覆盖教材第 2–10 章（见下方章节表）
- **播放器**：播放 / 暂停、上一步 / 下一步、进度条、首尾跳转、0.5–4× 变速、全屏、阶段分段跳转、键盘快捷键（空格、←/→、Home/End、F、1/2/3）
- **统一全屏**：舞台右上角用四角图标切换进入／退出全屏，悬停提示快捷键；主图、文字、箭头与辅助结构按可用空间等比缩放，全屏内保留步骤解读、播放控制、进度和倍速，窗口变化与步骤跳转后自动适配
- **图算法辅助结构**：DFS 图旁显示递归调用栈，BFS 图旁显示待扩展队列；邻接表构建同步展示顶点表与邻接结点链；拓扑排序显示实时入度、待输出栈和输出序列，已删除的依赖边用虚线保留
- **图的典型案例**：DFS／BFS 可选择非连通图，拓扑排序可选择有环图，Dijkstra 可选择目标不可达；输入框只填写顶点数，案例会随输入回放保留
- **自定义图**：BFS、DFS、Dijkstra、Bellman-Ford 和拓扑排序的舞台上方提供「自定义图」。输入 1–6 个字母顶点和边列表，在弹窗中实时预览后应用。BFS／DFS 的 `A B` 是无向边，Dijkstra 的 `A B 4` 是权重为 4 的有向边，Bellman-Ford 还接受 `A B -4` 等负权边。拓扑排序的 `A B` 表示 A 必须在 B 之前输出，无需指定起点。
- **自定义二叉树**：四种树遍历的舞台上方提供「自定义二叉树」。在弹窗中预览层序输入，点击「确定」后更新动画。输入 `A, B, C, null, D` 时，D 是 B 的右孩子。每个实际结点依次读取左右孩子，`null` 不再读取孩子，末尾空位可省略。最多 15 个结点。
- **分享演示**：播放控制区的「复制演示链接」记录已应用的输入和当前步骤。网站链接可直接回放。离线单文件版复制回放片段，可附到同一版本文件的地址末尾。
- **继续上次学习**：浏览器本地保存最近打开的演示、已应用的输入和当前步骤。在算法地图点击「继续上次学习」，即可回到当时的状态并暂停等待操作。
- **Dijkstra 计算表**：实时显示距离、前驱和确定状态，本步更新标绿；点击图中顶点或表中按钮查看并高亮路径，区分候选路径、已确定最短路径与不可达
- **Floyd 与最小生成树面板**：Floyd 展示完整距离矩阵，联动高亮目标与两个中转单元格；Prim 展示 lowcost、候选连接点和已选状态；Kruskal 展示连通分组、根与父指针，并标记合并和成环拒绝
- **树遍历调用栈与序列**：先序、中序、后序在树旁展示调用栈，在树下展示实际访问序列；单步、回退和拖动进度同步恢复，支持重复和负数结点值
- **递归可视化**：`TraceStep.callStack` 驱动变量面板的「调用栈」页签，阶乘、树遍历、快排都能看到栈的进出
- **自定义输入**：可改数据重新生成整条 Trace，带输入校验。BF、KMP 分别输入连续的主串和模式串，匹配时上下对齐显示
- **代码窗口**：C++ / Python 切换、当前行高亮、点击代码行跳到对应步骤、复制、行锚点对齐
- **变量面板、步骤解读、课程章节目录、搜索、浏览器本地学习进度（localStorage）**
- **图文讲解 + 随堂自测题**
- **练习中心**：根据当前舞台状态预测下一步。顺序栈、循环队列、单链表逆置、KMP 和两种哈希表提供具体操作题，答完可跳到同一输入的题目步骤
- **错题复习**：练习中心自动记录答错的题和当时选的答案，同一题重复答错只记一条。点击「只练错题」复习各算法的错题，作答后可看到复习前错选的答案，也可打开对应动画。复习答对后移出待复习列表，记录保存在当前浏览器。
- **用当前数据练习**：在 BFS、DFS、拓扑排序、Dijkstra 或中序遍历的播放控制区点击「用这组数据练习」，从当前步骤附近出题。自定义图支持预测出队、递归、拓扑出栈和判环，错题刷新后仍可复习、回放。
- **算法地图搜索**：在首页按名称、缩写或章节筛选算法，如 `BFS`、`KMP` 或「内排序」。
- **算法对比实验室**：同一组输入并排比较排序算法的状态、累计操作次数与终态，支持同步播放 / 暂停、前后单步、重置与 0.5–4× 调速；共同输入同时校验，成功应用数据或切换算法后停止播放并重置两侧进度
- **累计操作统计**：全部 9 个排序支持随进度查看关键字比较、交换、总写入，以及原数组与辅助数组/桶的写入明细
- **代码下载**：按当前编程语言导出代码。阶乘、AVL、Floyd、哈夫曼的下载文件使用当前输入，可用 C++17 或 Python 3 直接运行。其他算法会导出教学片段，并在注释中附上动画输入供参考。CI 用 `npm run test:examples` 核对可运行示例的结果与动画终态。
- **哈夫曼编码**：构造完成后显示树边的 0／1、字符编码、深度和 WPL 贡献，点选叶子或表中字符可高亮编码路径。
- **响应式布局**：桌面三栏、平板两栏、手机单栏 + 四标签切换（动画 / 目录 / 代码 / 讲解）

### 建议的学习方式

1. **先看状态，再看代码。** 在动画区用「下一步」确认指针、栈/队列、边和结点的变化；代码区会同步定位到产生这一步的语句，变量面板补充当前局部状态。
2. **主动预测。** 在「练习中心」先看操作前的状态，再判断出栈值、队尾下标、逆置指针、KMP 回退位置或哈希表的下一步探测与沿链查找。答完打开动画，单步验证。其他算法仍提供阶段预测，答题记录保存在当前浏览器。
3. **比较相同输入下的过程。** 在「算法对比实验室」选择两个排序，分别拖动进度条，观察比较、交换、写入次数如何累积，再用有序、逆序和重复值输入比较差异。
4. **从简单结构过渡到综合结构。** 推荐顺序为：线性表 → 栈和队列 → 串与递归 → 树 → 图 → 查找与排序。AVL 演示支持一次连续插入 3–7 个互异关键字，插入、更新高度、失衡判断和旋转均拆成独立步骤。

所有演示都能通过「重新生成」替换输入；同一套 Trace 同时驱动动画、代码高亮、变量、讲解和练习题，避免这些内容彼此脱节。

### 算法对比与计数规则

从顶部「算法对比」进入，选择左右算法，修改共同输入后点击「应用输入」或按回车。数据必须同时符合两种算法的长度、数值范围与特殊约束；例如基数排序要求非负整数。校验失败会显示原因并保留上一次结果，不会静默截断、补数或修改数值。若当前数据不符合待切换算法的要求，先修改并应用数据，再切换。

点击某侧「单独学习」时，会带上已应用的共同输入和该侧当前步骤。点击「返回对比」或使用浏览器后退，可恢复两个算法、共同输入和两侧位置，播放保持暂停。

成功应用输入（包括再次应用相同数据）或切换任一算法后，播放会停止，两侧回到第一步。

点击「同步播放」后，两侧每次各推进一个演示步骤；较短的一侧到终态后停住，另一侧继续，两侧都结束后自动暂停。支持暂停、上一步、下一步、重置和 0.5× / 1× / 2× / 4× 调速；结束后点击「重新播放」会从两侧开头开始。手动前后单步或拖动任一侧进度条都会暂停播放，之后可从各自当前位置继续。累计统计随所选步骤更新，拖回前面的步骤即可查看当时的计数。同步推进的是演示步骤，不能据此比较实际运行速度。

| 指标 | 统计口径 |
| --- | --- |
| 累计比较 | 排序过程中关键字大小的比较；不计下标、循环边界等控制条件 |
| 累计交换 | 两个数组位置交换一次计 1；赋值移位与挖坑填数不计交换 |
| 累计写入 | 原数组写入与辅助数组/桶的数据写入之和；一次交换计 2 次写入，相同值写回也计数 |
| 原数组写入 | 后移、填坑、插入、交换、归并回写、基数排序收集回写等 |
| 辅助数组/桶写入 | 归并排序写入辅助数组、基数排序把元素分配进桶；计入累计写入 |
| 步骤数 | 演示快照的数量，受讲解拆分方式影响 |

计数对应展示的教学算法，不统计临时变量赋值、数组初始化、清空、桶计数器及演示快照的内部操作。基数排序按位分桶，关键字比较次数为 0；这不代表它没有计算成本。操作次数与步骤数均不等同于运行耗时。

## 校验覆盖

`npm run validate` 干两件事：**查格式**（行锚点对齐、图元 id 唯一、指针下标不越界、步骤连续）与**查结果**（独立重算一遍再比对，不复述算法自己报的答案）。

操作统计由 `scripts/sort-metrics.mjs` 验证，包含全部 9 个排序的 **76 组算法与输入组合**，覆盖有序、逆序、全相等、重复值、负数与零、双向填坑、最短输入、希尔多增量、堆的多层下沉及基数排序的 1–3 位数据。检查手算累计次数、辅助写入、快照独立性、计数单调性与终态排序结果；负数用例不用于基数排序。

同步播放状态由 `scripts/comparison-playback.mjs` 的 **11 组用例**验证，覆盖不同长度的推进与自动停止、暂停后的时钟事件、独立拖动、前后单步、重播、重置、调速和进度边界。

| 类别 | 独立验证方式 | 覆盖算法 |
| --- | --- | --- |
| 排序 | 终态升序 + 与输入同一多重集合 | 全部 9 个排序 |
| 排序操作统计 | 固定输入的手算结果 + 累计快照检查 | 全部 9 个排序 |
| 查找 | 命中的值等于待查目标 | 顺序 / 折半 / BST 查找 / 两种哈希 |
| 串匹配 | 用 `indexOf` 独立求首次出现位置 | BF、KMP |
| 最小生成树 | 独立跑 Kruskal 求权值 + 检查无环 | Prim、Kruskal |
| 单源最短路 | 按图重建邻接表重跑 Dijkstra | Dijkstra |
| 多源最短路 | 独立跑 Floyd-Warshall 比对完整结果矩阵，逐步检查目标更新和其他单元格保持 | Floyd |
| 带负权最短路 | 独立跑 n-1 轮松弛 | Bellman-Ford |
| 拓扑排序 | 检查输出序列满足每条有向边，并逐步校验 3–6 个顶点的栈内容、栈顶、删边、实时入度与输出快照 | 拓扑排序 |
| 关键路径 | 独立求 ve / vl + 校验关键活动条件 | 关键路径 |
| 树遍历 | 重建树结构后独立遍历比对访问顺序 | 先/中/后/层序 |
| 二叉排序树 | 中序遍历必须有序 | BST 插入 |
| 哈夫曼树 | 根权值 = 叶子权值之和 | 哈夫曼 |
| 压缩存储 | 按公式独立算下标比对落位值 | 对称/三对角/三元组 |

栈与队列回归用例覆盖原始输入保留、后进先出与先进先出、循环队列补充值与回绕。播放器和练习回归用例覆盖换页暂停、旧计时器、学习记录归属，以及练习答案和回放步骤。

链表校验逐帧对照四种单链表建表、按值查找、双链表插入、单链表逆置和约瑟夫环的工作指针与连线。DFS／BFS 校验独立计算 3–6 个顶点的访问顺序与首次发现边，逐帧检查箭头出现时机、方向、保留状态和顶点着色，以及调用栈进出、队列先进先出与图顶点的对应关系。

图案例回归覆盖 DFS／BFS 连通与非连通图的 16 组用例、拓扑排序有环的 4 组用例，以及 Dijkstra 的 8 组逐步距离、前驱和路径快照；最短距离使用 Bellman-Ford 独立求解比对。

教学面板另有 22 组固定用例，覆盖完整 Floyd 矩阵、Prim 各轮候选连接、Kruskal 分组和父指针一致性，以及三种树遍历的调用栈、访问序列和重复／负数输入。

Bellman-Ford 的动画与代码均在一整轮无更新时提前结束松弛，再执行额外的可达负权回路检测。3 组固定用例检查实际轮数、提前退出后不再松弛、检测不增加轮次及最终距离；桌面和窄屏浏览器检查相同流程及回退恢复。

### 浏览器回归

首次使用需安装 Chromium 和 WebKit，之后构建并运行测试：

```bash
npx playwright install chromium webkit
npm run standalone
npm run test:browser
```

测试在独立端口 `41080` 启动生产预览，覆盖桌面与窄屏、图例和典型案例、Dijkstra 表与路径选择／回退、53 个演示的全屏首中末步骤、播放／暂停、单步、进度、倍速、窗口变化及退出恢复。失败截图、跟踪和报告写入 `test-results/`、`playwright-report/`，均不提交到 Git。

另检查切换算法清空自测答案、代码行的 Enter／空格跳转，以及 `standalone.html` 在 `file://` 和断网环境下访问动画、对比与练习页面。网站按页面懒加载，单文件版单独合并全部模块并内联 CSS／JS，避免依赖额外资源。

全屏布局与控件使用明确标记的模拟全屏用例，始终执行；另有桌面原生全屏用例，浏览器不授予全屏权限时会标明原因并跳过。CI 在 Chromium 上运行完整回归，并在 WebKit 上检查语言切换、自定义图和树弹窗，以及离线单文件。配置方式参考 [Playwright Web Server](https://playwright.dev/docs/test-webserver) 和 [CI 文档](https://playwright.dev/docs/ci-intro)。

KMP 校验独立枚举模式串各段的真前后缀，逐帧检查 `next` 的写入、失配回退、哨兵 `-1` 和首次匹配位置。

哈希表校验逐帧核对线性探测的冲突、回绕、落位与查找，以及拉链法的桶下标、尾插顺序和查找路径。用例包括负数、重复键、表满和找不到目标。

## 如何贡献一个新算法

一个算法 = 一个 `.ts` 文件 + 一行注册，适合按章节提 PR：

1. 挑一个同类算法复制，改 `slug / title / chapter / category / summary / complexity`。
2. 在 `generate(input)` 里用 `makeStep(id, anchor, phase, scene, vars, caption)` 逐步产出快照。要点：
   - 每一步的 `scene` 必须是**独立快照**，不要复用上一步的对象；
   - 图元 `id` 全程稳定，渲染层靠它做位移动画；
   - `anchor` 用语义名（如 `cmp`、`swap`），**不要写行号**。
3. 选对场景构造函数（都在 `src/engine/scene.ts`）：

   | 结构 | 构造函数 | 说明 |
   | --- | --- | --- |
   | 顺序表 / 数组 | `arrayScene(nodes, pointers, capacity, note)` | 固定格子，空格子也占位 |
   | 链表 | `listScene(nodes, pointers, note, detached)` | `detached` 表示尚未接入链的结点 |
   | 矩阵 / 哈希表 | `gridScene(nodes, cols, pointers, note)` | 按 `cols` 折行成二维网格 |
   | 二叉树 | `treeScene(nodes, edges, note)` | 只描述父子边，坐标由 `layoutTree` 自动算 |
   | 图 | `graphScene(nodes, edges, note, pointers)` | 边可带权值 `label`；结点可用 `nodeAt` 指定归一化坐标 |

4. 在 `code.cpp` 与 `code.python` 的对应行上标出**完全相同**的 anchor 集合；切换语言靠它对齐，缺一个 `npm run validate` 就会报错。
5. 如果算法对输入有特殊要求（只能是顶点个数、非负整数、带编码的串……），用 `input` 字段声明，不要在 `generate()` 里静默回退默认数据：

   ```ts
   input: {
     min: 3, max: 6, minLen: 1, maxLen: 1,      // 值的范围、元素个数
     check: (v) => (v.some((x) => x < 0) ? '需要非负整数' : null),
     random: () => [3 + Math.floor(Math.random() * 4)],  // 「随机」按钮的数据来源
   }
   ```

   页面上的输入校验、错误文案、「随机」按钮全部由它驱动。**每个算法都应声明 `input`**。`npm run validate` 会检查默认输入、随机样本和更换输入后的轨迹。
6. 补 `doc`（图文讲解）与 `quiz`（自测题）。
7. 在 `src/algorithms/registry.ts` 的 `algorithms` 数组登记，并把 slug 填进对应章节的 `slugs`。
8. 跑 `npm run validate`，通过后即可提交。它除了检查格式，还会独立重算一遍结果做比对（见下方「校验覆盖」）——如果你的算法属于还没被覆盖的类别，记得在 `scripts/assertions.mjs` 里补断言。

新增排序算法还需为每个步骤提供独立的 `metrics` 累计快照，在对应操作发生后递增计数，初始步骤从 0 开始。例如：

```ts
step.metrics = {
  comparisons,
  swaps,
  writes: mainWrites + auxiliaryWrites,
  auxiliaryWrites, // 不使用辅助数组时可省略，按 0 处理
};
```

字段定义见 `src/engine/types.ts` 的 `SortMetrics`。在 `scripts/sort-metrics.mjs` 中登记新算法和手算用例，并运行 `npm run validate`；应同时验证最终计数与各步快照，确保回退和拖动进度时统计一致。

边与结点的状态取值见 `src/engine/types.ts`：结点 9 种（`default / active / compare / min / sorted / insert / delete / found / visited`），边 6 种（`default / tree / active / candidate / reject / removed`）。`removed` 表示已删除的依赖边，以浅灰虚线显示。状态色统一在 `Stage.tsx` 维护，新增状态需同步更新 `design.md` §2.1。
