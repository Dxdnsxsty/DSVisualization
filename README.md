# 数据结构可视化

面向《数据结构》课程学习者的**开源、纯静态**算法可视化网站。分步播放算法执行过程，代码行、数据状态、变量与文字讲解由同一个步骤对象同步驱动。

算法与章节按《数据结构教程》（李春葆等，第 5 版）编排，共 **50 个算法、覆盖 9 个可视化章节**。

无登录、无后端、无数据库、无外部 API，可直接用 GitHub Pages 托管。

## 本地运行

需要 Node.js 20+（开发环境为 Node 22）。

```bash
npm install
npm run dev        # 打开 http://127.0.0.1:5180
```

其他命令：

```bash
npm run validate     # 校验 Trace 格式 + 独立重算结果（排序是否有序、MST 权值、最短路径、拓扑序…）
npm run build        # 类型检查 + 构建到 dist/
npm run preview      # 本地预览构建产物
npm run standalone   # 构建并生成 dist/standalone.html 单文件版
```

打开后默认进入「算法地图」，按章节挑一个算法即可进入三栏工作台：左侧课程目录、中间动画舞台与播放控制、右侧代码与变量。点「播放」或「下一步」即可看到动画、代码高亮、变量面板同步变化。

**发给同学最省事的方式**：执行 `npm run standalone`，把生成的 `dist/standalone.html` 直接发出去。它把 JS/CSS 全部内联，双击即可打开，不需要 Node、不需要服务器、不需要联网，课程群里传一个文件就能演示全部 50 个算法。

## 端口说明（Windows 报 EACCES 时看这里）

开发服务器默认用 **5180**，而不是 Vite 常见的 5173。原因是 Windows 的 Hyper-V / WSL2 / Docker 会保留一段 TCP 端口，本机实测保留段包含 `5076–5175`，绑定 5173 会报：

```
Error: listen EACCES: permission denied 127.0.0.1:5173
```

这通常**不是端口被占用**（那会报 EADDRINUSE），而是系统保留端口导致绑定被拒绝。排查：

```powershell
netsh interface ipv4 show excludedportrange protocol=tcp
netstat -ano | findstr ":5180"
```

换端口有两种方式：`npm run dev -- --port 8080`，或直接修改 `vite.config.ts` 里的 `server.port`。选一个不在排除范围内的端口即可；本机实测 4173 / 5180 / 8080 / 8888 可用。

若报 `Port 5180 is already in use`，说明已经有一个开发服务器在跑了（比如另一个终端没关，或 IDE 预览进程还挂着）：直接打开 `http://127.0.0.1:5180/` 即可，不必重复启动。想彻底重来就先关掉旧进程，或用 `--port 8080` 换一个端口。配置里设置了 `strictPort: true`，端口被占用时会明确报错而不是悄悄换成 5181。

## 部署到 GitHub Pages

1. 把仓库推到 GitHub，分支名为 `main`。
2. 在仓库 Settings → Pages → Build and deployment 中选择 **GitHub Actions**。
3. `.github/workflows/deploy.yml` 会自动执行 `validate → build → deploy`，无需任何密钥。
4. 若仓库名不是根域名，也不用改配置：`vite.config.ts` 使用相对 `base`，路由是 hash 形式，项目页路径可直接工作。

本地验证静态托管效果：`npm run build` 后用任意静态服务器打开 `dist/index.html` 即可。

## 功能范围

**已实现**

- **Trace 引擎**：`TraceStep[]` 状态序列 + 唯一 `currentStep`，倒放 / 拖拽进度天然一致
- **四类可视化场景**：数组、链表、树、图；另支持二维网格（矩阵 / 哈希表折行）与辅助结构条（归并目标数组等）
- **50 个算法**，覆盖教材第 2–10 章（见下方章节表）
- **播放器**：播放 / 暂停、上一步 / 下一步、进度条、首尾跳转、0.5–4× 变速、全屏、阶段分段跳转、键盘快捷键（空格、←/→、Home/End、F、1/2/3）
- **递归可视化**：`TraceStep.callStack` 驱动变量面板的「调用栈」页签，阶乘、树遍历、快排都能看到栈的进出
- **自定义输入**：可改数据重新生成整条 Trace，带输入校验
- **代码窗口**：C++ / Python 切换、当前行高亮、点击代码行跳到对应步骤、复制、行锚点对齐
- **变量面板、步骤解读、课程章节目录、搜索、浏览器本地学习进度（localStorage）**
- **图文讲解 + 随堂自测题**
- **练习中心**：从 Trace 自动抽取“预测下一步”题目，练习记录只保存在浏览器本地
- **算法对比实验室**：同一组输入并排比较排序算法的动画、步骤数与终态
- **代码下载**：按当前语言导出教学示例及当前输入说明
- **响应式布局**：桌面三栏、平板两栏、手机单栏 + 四标签切换（动画 / 目录 / 代码 / 讲解）

### 建议的学习方式

1. **先看状态，再看代码。** 在动画区用「下一步」确认指针、栈/队列、边和结点的变化；代码区会同步定位到产生这一步的语句，变量面板补充当前局部状态。
2. **主动预测。** 进入「练习中心」完成由真实 Trace 自动生成的“预测下一步”题；答题记录仅保存在当前浏览器，可随时清除重练。
3. **比较相同输入下的过程。** 排序算法可在「算法对比实验室」并排运行：两边共享同一组数据，便于区分比较次数、交换方式和最终步骤数。
4. **从简单结构过渡到综合结构。** 推荐顺序为：线性表 → 栈和队列 → 串与递归 → 树 → 图 → 查找与排序。AVL 演示支持一次连续插入 3–7 个互异关键字，插入、更新高度、失衡判断和旋转均拆成独立步骤。

所有演示都能通过「重新生成」替换输入；同一套 Trace 同时驱动动画、代码高亮、变量、讲解和练习题，避免这些内容彼此脱节。

## 校验覆盖

`npm run validate` 干两件事：**查格式**（行锚点对齐、图元 id 唯一、指针下标不越界、步骤连续）与**查结果**（独立重算一遍再比对，不复述算法自己报的答案）。

| 类别 | 独立验证方式 | 覆盖算法 |
| --- | --- | --- |
| 排序 | 终态升序 + 与输入同一多重集合 | 全部 9 个排序 |
| 查找 | 命中的值等于待查目标 | 顺序 / 折半 / BST 查找 / 两种哈希 |
| 串匹配 | 用 `indexOf` 独立求首次出现位置 | BF、KMP |
| 最小生成树 | 独立跑 Kruskal 求权值 + 检查无环 | Prim、Kruskal |
| 单源最短路 | 按图重建邻接表重跑 Dijkstra | Dijkstra |
| 多源最短路 | 独立跑 Floyd-Warshall 比对结果行 | Floyd |
| 带负权最短路 | 独立跑 n-1 轮松弛 | Bellman-Ford |
| 拓扑排序 | 检查输出序列满足每条有向边 | 拓扑排序 |
| 关键路径 | 独立求 ve / vl + 校验关键活动条件 | 关键路径 |
| 树遍历 | 重建树结构后独立遍历比对访问顺序 | 先/中/后/层序 |
| 二叉排序树 | 中序遍历必须有序 | BST 插入 |
| 哈夫曼树 | 根权值 = 叶子权值之和 | 哈夫曼 |
| 压缩存储 | 按公式独立算下标比对落位值 | 对称/三对角/三元组 |

暂未覆盖：栈与队列的进出语义、DFS/BFS 访问顺序、链表指针操作、哈希插入落位、KMP 的 next 数组。

## 如何贡献一个新算法

一个算法 = 一个 `.ts` 文件 + 一行注册，适合按章节提 PR：

1. 挑一个同类算法复制，改 `slug / title / chapter / category / summary / complexity`。
2. 在 `generate(input)` 里用 `makeStep(id, anchor, phase, scene, vars, caption)` 逐步产出快照。要点：
   - 每一步的 `scene` 必须是**独立快照**，不要复用上一步的对象；
   - 图元 `id` 全程稳定，渲染层靠它做位移动画；
   - `anchor` 用语义名（如 `cmp`、`swap`），**不要写行号**。
3. 选对场景构造函数（都在 `src/engine/scene.ts`）：

   | 结构 | 构造函数 | 说明 |
   | --- | --- | --- |
   | 顺序表 / 数组 | `arrayScene(nodes, pointers, capacity, note)` | 固定格子，空格子也占位 |
   | 链表 | `listScene(nodes, pointers, note, detached)` | `detached` 表示尚未接入链的结点 |
   | 矩阵 / 哈希表 | `gridScene(nodes, cols, pointers, note)` | 按 `cols` 折行成二维网格 |
   | 二叉树 | `treeScene(nodes, edges, note)` | 只描述父子边，坐标由 `layoutTree` 自动算 |
   | 图 | `graphScene(nodes, edges, note, pointers)` | 边可带权值 `label`；结点可用 `nodeAt` 指定归一化坐标 |

4. 在 `code.cpp` 与 `code.python` 的对应行上标出**完全相同**的 anchor 集合；切换语言靠它对齐，缺一个 `npm run validate` 就会报错。
5. 如果算法对输入有特殊要求（只能是顶点个数、非负整数、带编码的串……），用 `input` 字段声明，不要在 `generate()` 里静默回退默认数据：

   ```ts
   input: {
     min: 3, max: 6, minLen: 1, maxLen: 1,      // 值的范围、元素个数
     check: (v) => (v.some((x) => x < 0) ? '需要非负整数' : null),
     random: () => [3 + Math.floor(Math.random() * 4)],  // 「随机」按钮的数据来源
   }
   ```

   页面上的输入校验、错误文案、「随机」按钮全部由它驱动。**50 个算法都必须声明 `input`**：`npm run validate` 会检查 `defaultInput` 是否合规、连续多次「随机」采样是否都合法，并额外验证"换一组合法输入后轨迹必须变化"——防止出现"校验通过但生成器悄悄回退默认数据"的缝隙。
6. 补 `doc`（图文讲解）与 `quiz`（自测题）。
7. 在 `src/algorithms/registry.ts` 的 `algorithms` 数组登记，并把 slug 填进对应章节的 `slugs`。
8. 跑 `npm run validate`，通过后即可提交。它除了检查格式，还会独立重算一遍结果做比对（见下方「校验覆盖」）——如果你的算法属于还没被覆盖的类别，记得在 `scripts/assertions.mjs` 里补断言。

边与结点的状态取值见 `src/engine/types.ts`：结点 9 种（`default / active / compare / min / sorted / insert / delete / found / visited`），边 5 种（`default / tree / active / candidate / reject`）。状态色统一在 `Stage.tsx` 维护，新增状态需同步更新 `design.md` §2.1。
